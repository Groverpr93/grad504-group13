## Preprocessing all supplied datasets

Run preprocessing before graph construction:

```bash
python src/preprocess_kiva.py --data-dir data/raw --output-dir data/processed
```

This joins the primary loan table to the theme, regional MPI, and country
profile tables and writes `data/processed/loans_joined.csv`,
`data/processed/loan_partner_edges.csv`, `data/processed/graph_nodes.csv`, and
`data/processed/join_report.json`. The report records match rates and examples of
unmatched keys; some MPI rows are expected to remain unmatched because the
Kiva loan locations are much more granular and inconsistently named than the
MPI reference table. The joined table labels MPI values as exact loan-region,
theme-region, location, or country-average proxy matches using
`mpi_match_type`; proxy values should be treated as lower-confidence features.
Use `--max-loans 10000` for a quick development check and
`--max-loans 0` (the default) for the complete dataset.

## Graph and learning objective

Each loan is a node. Each Kiva field partner is a node, and region and
borrower-gender values are context nodes. The observed loan-partner association
is the positive target edge. Loan-to-region and loan-to-gender edges give the
encoder additional context; all message-passing edges are represented in both
directions. A randomly sampled loan-partner pair with no observed association
is a negative edge.

GraphSAGE produces an embedding `z_v` for every node. A candidate link receives
the score `s(u,v) = z_u dot z_v`. The training objective is binary
cross-entropy over positive and negative edges:

`L = -mean[y log(sigmoid(s)) + (1-y) log(1-sigmoid(s))]`.

The encoder graph contains training-period edges only, preventing future-edge
leakage into validation or test embeddings.

- temporal train/validation/test split (70/15/15), with negative sampling;
- link ranking metrics: ROC-AUC, average precision, Hits@5, and NDCG@5;
- selection-rate gaps for borrower gender and region, with a 5% maximum gap;
- guardrail violation rate (target 0%) and elapsed runtime.

The project uses one direct GNN script. It samples 50,000 loans by
default to make a first run practical; pass `--max-loans 0` for the full CSV.

```bash
python -m pip install torch
python src/gnn_link_pred.py \
  --data-file data/processed/loans_joined.csv \
  --max-loans 50000 \
  --epochs 20 \
  --results-file outputs/evaluation/gnn_results.json
```

The GNN script performs core link prediction only. Fairness remains a
separate secondary phase to add after the ranking model is stable.

Install PyTorch in the project environment. The script prints each training
epoch and stores the core result in `outputs/evaluation/gnn_results.json`.
